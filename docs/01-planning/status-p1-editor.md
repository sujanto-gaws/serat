## Design rulings made during implementation (all merged)

- **ADR-0015 §2:** the open-time catch-up always compares mtimes (a `git pull` while Serat is closed must be seen); `clean_close` only schedules the background `quick_check`. Coarse-mtime gap closed by `notes.size` plus a racy window `caught_up_from_ms` (#66); the window is stamped immediately before the watcher is armed (#78). `Vault::read` stats the open handle before reading; `TouchMtime` is hash-guarded.
- **§3.1.1 hub-note save (#53 → #56):** the WAL auto-checkpoint landed on every second hub save; it now runs on its own thread with a 250 ms idle gate, 2 s idle spacing and a 4,000-frame bound; search connection cache 64 MiB. Attested quiet run: **p95 23.3 ms vs 50 ms**.
- **§9.2 quick switcher:** 20k gates, 50k reported; empty query falls back to most-recent-by-mtime; per-query DP cell budget; history written by `Vault::update_history`.
- **§9.3 NFR-PRF-02:** E0 rule, two per-run invariants (keydown present; entry-end spread ≤8 ms, derived), engine version on every figure, graded arm informational and per-version, key window [t−0.01, t+4]. Headless end-of-document stall recorded; scroll margins are load-bearing for the measurement until the reference-machine run tests both builds.
- **ADR-0017:** handler accepts `serat-asset://localhost/…` on every platform (wry reverts its Windows rewrite); step 7 reads the handle's real path via `filepath`; `use_https_scheme(false)` pinned on the window builder.
- **#63 clean close:** `app://closing` → editor flush → `flush_ack`, bounded 2 s, only when a note is open; close and switch serialised on `opening`.
- **§3.4 vault id (#79, #90, #103, #91):** `BootInfo.vault_id` at launch, `vault://opened` after every later open; the failed-open window is bounded, not absent — after a `choose_vault` Err the front end drops every event carrying the announced id; the index-status fallback is restricted to launch.
- **ADR-0017 Amendment 1 (#94) and the granularity clause (#110):** pdf.js 6 has no eval path, the CSP is the control; `PDFDataRangeTransport` over `read_asset_range` everywhere; `AssetInfo.etag` + `if_match` → `IpcError::AssetChanged` (#98, #108); the validator misses a same-size rewrite within the kernel's coarse-clock tick before Linux 6.13 and an mtime-preserving writer; the inode would close the rename cases only. cMaps/standard fonts are a recorded gap.
- **§9.3 one registry (#25, #43, #39):** the palette, switcher, tree menu and ⌘N/⌘⇧N all go through `CommandRegistry`; the tree menu's Insert-link chord is still hard-coded (follow-up owed). The native webview context menu is suppressed outside editable text on every platform (T-07); the Rust-side suppression covers Linux release builds only.
- **#58:** a parser-refused note is a bare row on every path (C-02).
- **ADR-0019 (#166, #169; C-06, NFR-PRF-08):** a budget is enforced where a gate number can be produced: on the reference machine at each gate with the scanner on, and in CI on every runner the harness rates gate-eligible; a CI job on an ineligible runner measures, prints REPORT-ONLY and fails only if it cannot measure (degraded runs and budgets with a `ci_limit_ms` always assert); a report-only budget also gets an asserting `ubuntu-latest` job; NFR-PRF-01/03 stay asserted until their first hosted numbers; `COALESCE_WINDOW` stays 150 ms; best-of-three is rejected; RM-1 has only run scanner-off, so a Defender-on RM-1 run is owed before any budget counts as enforced.
- **Live-preview typography (#160–#162; FR-EDT-02):** links keep a quiet underline at rest (indigo on ink is 1.9:1, colour alone cannot mark a link); revealed markers appear in the same frame with no fade and only the marker runs go mono; bullets become glyphs and ordered numerals are never hidden; frontmatter detection matches the index's exact `---` closer with a 200-line cap; floating layers (tree menu, external-edit notice) use `--serat-surface-overlay`, in-flow tints use `--serat-surface-raised`; `.cm-content` top padding is 16 px because CodeMirror's 24 px scroll margin left Control+Home 6 px short; `measure.editor` is 72ch (71–74 characters per line with the real Source Serif 4; 64ch gave 59–69); the editor mounts immediately with `font-display: swap` and `requestMeasure` on `loadingdone` (gating the mount would cost NFR-PRF-01); the #137 stylesheet guard allows `url()` only in an `@font-face` `src` and only for relative, scheme-less paths. **#57:** block-style frontmatter lists are indexed (aliases were 0 rows before). **#59:** no unsafe carve-out for cache diagnostics.

- **ADR-0020 (#173; NFR-PRF-03, FR-VLT-04) with PRD v1.13 (#174):** the save path's read, hash and parse stay on the command thread in P1 (the command runs on the blocking pool; close ordering rests on the submit happening inside the command; ordering against the watcher is a timing bound, recorded as an open design question); the index-handle slot lock is released before the parse (F-382); a save's `index://changed` moves from the submit to the index writer's post-commit observer, the single announcement producer outside a rebuild (today a pane or the link resolver re-reading on the event can see the pre-commit snapshot). PRD v1.13: NFR-PRF-03 binds the note class its two gating scenarios sample and adds a reported, non-gating 5,000-line scenario; the 50 ms target is unchanged; #172's whole-command figure neither passes nor fails it.
