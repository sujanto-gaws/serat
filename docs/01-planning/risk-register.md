# Risk Register — Serat

Severity as stated in the blueprint, except RISK-012, which was raised during the P0 spike, and RISK-013 to RISK-015, which were raised during P0 and P1. Likelihood and impact to be split out once P0 produces real numbers. Owner is the lead unless reassigned.

| ID | Risk | Severity | Mitigation | Owner | Status |
|---|---|---|---|---|---|
| RISK-001 | Write-back corrupts notes | Critical | Byte-range patches only; hash guard (stale-range rejection); atomic rename; git auto-commit before any view-originated write in first releases. Property-test the patcher against a corpus of real notes. | lead | Open — de-risk standalone before P2 (next move #4) |
| RISK-002 | Rust ramp-up eats the schedule — **P0 evidence contradicts this: the cost is coordination, not Rust (F-07)** | High, re-rate | Small, boring Rust surface; product logic pushed into SQL and Vue; no async-framework gymnastics. P0 exists partly to measure this friction before committing 30 weeks. | lead | **Open, re-rate not close.** P0 measured no Rust friction worth an hour: serat-vault compiled first try, 35 of 40 tests passed on the first run, two clippy findings across two tasks, rusqlite built SQLite unattended. All three real costs were coordination — a workspace-wide gate red because another teammate's crate was mid-edit, the repository appearing mid-task, and untracked `bench/` breaking `cargo metadata` in every worktree at once. The risk to carry into P1 is that the workspace is one shared object with many owners, a cost scaling with teammates rather than lines of code. |
| RISK-003 | CodeMirror 6 hybrid live preview is deep water | High | Largest single frontend cost. Start from an existing CM6 Markdown live-preview implementation, not from zero; time-box inside P1; fall back to split preview if it overruns. | lead | Open — P1: split preview (FR-EDT-10) is built in the same task (#21) as the fallback; NFR-PRF-02 harness (#11) lands first. |
| RISK-004 | Binary parsing is an attack surface | High | Every extractor runs in a short-lived child process with wall-clock limit, memory cap and no network; a crash marks the file unextractable instead of taking the app down. Fuzz the MIME dispatcher, not just the parsers. | lead | Open — P2 |
| RISK-005 | Solo project loses momentum | High | Phase gates chosen so each phase ends with something the owner uses daily. Dogfooding is the momentum plan. | lead | Open — ongoing |
| RISK-006 | Obsidian's plugin ecosystem (breadth is unwinnable) | Medium | Do not compete on breadth. Compete on the pillars plus vault compatibility, so leaving Obsidian is never all-or-nothing. | lead | Accepted |
| RISK-007 | Scope creep into "second Obsidian" | Medium | The "deliberately not" list in the charter is the contract. Anything on it needs an explicit decision to reopen. | lead | Open — ongoing |
| RISK-008 | Obsidian closes the gap (Bases keeps improving) | Medium | Lead with what is hardest to copy — writable views and a core AI layer — not query syntax. | lead | Open — watch |
| RISK-009 | Extractors are a long tail | Medium | One format per iteration behind a trait: PDF first, Office next, rest optional. A format with no extractor still indexes as a typed asset row; coverage gaps degrade capability rather than breaking the vault. | lead | Open — P2 |
| RISK-010 | Embedding model ships as a fat binary | Low | Download the model on first AI use, not at install. The app must be fully useful with the AI layer never enabled. | lead | Open — P4 |
| RISK-011 | Name collision with Serato (DJ software) if the product goes public | Low | Watch search results; revisit naming before any public launch. | lead | Open — watch |
| RISK-012 | Budget numbers are measured on a machine no user runs | High | RM-1 has Windows Defender real-time protection disabled and runs a power-saving profile; a full rebuild reads 20,000 files, so every NFR-PRF-04 figure taken there is a Windows best case. Measure NFR-PRF-04 and NFR-PRF-01 both with Defender on and off; the gate is judged against the Defender-on number. Never disable protection to make a budget pass — a breach is a NO-GO and an architecture finding (§1.2), not an environment footnote. | test-engineer | Mitigated in code — P0. `bench/budget/src/env.rs` detects the real-time scanner state and power plan on every run and stamps both on each result; a scanner-disabled run is marked `gate_eligible: false` and prints NOT A GATE NUMBER, and an *undetermined* state is also ineligible. **Task #166 (2026-11-23):** all 36 hosted `windows-latest` runs report scanner OFF on 2 cores, so a hosted run is never gate eligible; NFR-PRF-04 is `CiAssertion::WhenGateEligible`, report-only there and asserted on the reference machine (`nfr-prf-04-gate-quality.md`, "Task #166"). The earlier claim that hosted runners have the scanner on was wrong and is corrected in reference-machine.md. The harness never toggles the scanner — disabling antivirus to make a number look good is not a capability this project ships. Protocol in reference-machine.md; standing rule in test-plan.md. |
| RISK-013 | Budgets are not enforced in CI (C-06) because most CI runs get no hosted runner (F-384; runners executed on 2026-09-06 and, since ci run 87, only on 2026-10-20/21 and 2026-11-09 (about 38 `budgets.yml` runs, none green); the billing / spending-limit pattern; owner checks Actions billing, then Settings, Actions, General, then re-runs `ci.yml` and `budgets.yml` on `main`) | High | Owner fixes the repository's Actions configuration; until then every P1 budget job runs locally, fails loudly, and the P1 gate report states which budgets were CI-asserted (none, today). | owner | Open — accepted by owner decision 2026-09-24 to enter P1. Task #166: NFR-PRF-04 is not CI-asserted on hosted Windows (report-only); closing step once runners schedule is test-engineer's `[P1/test]` Windows re-run task: three `budgets.yml` dispatches on the head, PRF-04 and FR-VLT-04 lines recorded in nfr-prf-04-gate-quality.md |
| RISK-014 | FR-VLT-01 file tree misses its 2 s budget by 4x and scales linearly (F-12, F-193) | High | Design change before any tree code (P1 task #2, ADR-0015); bench (#9) lands before implementation (#13). | architect | Open — P1 critical path |
| RISK-015 | Cloud online-only files are downloaded by background work in P1 (ADR-0018's P1 interim): a rebuild over a OneDrive Files-On-Demand or iCloud "Optimize Mac Storage" vault is network-bound and downloads the vault; the watcher can re-download a file the user has just freed; a not-local directory makes the tree walk fetch its listing over the network, so FR-VLT-01 and NFR-PRF-04 do not hold on such a vault. Today a placeholder opened through `read_file` downloads on whichever thread serves the command, which is the webview main thread until task #49 makes `read_file` async | Medium. The owner's "local only" answer covers the primary machine. **Trigger:** a synced replica of the real vault (p1-gate-protocol.md: any copy, clone or synced replica is the real vault) under OneDrive Files-On-Demand or iCloud "Optimize Mac Storage" reopens the P1 question and raises this to High | P1: a failed or interrupted read is an error, never zero bytes, so a download that fails offline cannot truncate a note (goal 1); `serat_core::locality::is_local` lands with tests. P2: ADR-0018's rule (only an explicit open downloads), proposed as a P2 Must FR-VLT requirement. | architect | Open — accepted for P1; closed by ADR-0018's P2 rule |
