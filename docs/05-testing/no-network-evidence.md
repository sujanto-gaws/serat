Serves NFR-SEC-01 (no telemetry; US-34; verification Test), NFR-SEC-02 / T-02 (no unconfigured network), T-01 (no telemetry: the deny-list is its mechanism), T-05 (no TCP listener: the source scan), T-09 (a note fetching a remote resource: the CSP and webview tests); ADR-0017 (the two scheme origins).

Each scanner has a test that it fails on the thing it exists to find (the F-30 lesson: a guard that cannot fail is not a guard). The dependency-graph tests run `cargo tree --locked` and not `--offline`: `cargo test` has not downloaded the other targets' crates on a clean runner, and `--offline` fails there. The tree command fetches what it needs; `--locked` keeps the lockfile in charge.

## Findings recorded while writing it (not silenced)

- `tauri` lists `reqwest` as a dependency for Android and iOS only; `cargo metadata` without a platform filter therefore shows `reqwest` and `hyper` in the graph. The test uses per-target `cargo tree`, which is what is compiled. It is kept to desktop targets: a mobile target would fail it, correctly.
- Present on Windows, macOS and Linux and not network clients here: `tokio` (without `net`), `http`, `url`, `urlpattern`.
- Present on Linux only: `mio` (`notify`'s inotify poller; `net` feature off) and, through `tauri-plugin-opener`, `zbus`, `async-io`, `polling`, `async-process` and `blocking`. `zbus` is a D-Bus client. It connects to the session bus, which is normally a unix socket, but it follows a `tcp:` `DBUS_SESSION_BUS_ADDRESS` if the user's environment sets one. That is the environment's choice, not a connection Serat chooses; it is on `KNOWN_NON_NETWORK` with this reason, and it is the one entry a reviewer should re-read when `tauri-plugin-opener` changes.
- The bundles contain a documentation-link string from Vue's production error handler (`https://vuejs.org/error-reference/...`) and pdf.js's URL-parsing bases (`https://foo.bar`, `http://example.com`). None is requested; each is on the inert table with its reason and count.
- The CSP has no `form-action` or `base-uri` directive, and ADR-0017 item 6 speaks of `connect-src 'self'` where the CSP has the IPC and scheme origins. Neither is changed by this task; both are for the architect. **Ruled by task #115 (ADR-0017 Amendment 2):** `form-action 'none'; base-uri 'none'` are added and pinned. Item 6 is corrected: today's CSP would block the cMap and font fetches, and the change that ships them adds `'self'` to `connect-src`, re-pinning the string and updating item 4 above in the same commit.

## Limits (read before relying on this)

This proves the **absence of code paths** in what we compile and ship. It does not observe a running process, so it cannot show that no connection is opened by the operating system's webview (update checks, safe-browsing lookups, DNS prefetch, proxy auto-detection), by a library through a path the scanners do not know, or by a crate added later under a name not on the deny-list. The deny-list is a list of names; the graph review at each dependency change keeps it honest. The webview scan reads strings, so a URL assembled at run time from pieces is invisible to it, as are indirect calls (`globalThis["fetch"]`, `window.fetch.call`), which are the CSP's to stop, and so is a protocol-relative `//host/x` (it has no scheme to match); the CSP pin (4) is the enforcement and the scans are evidence.

The committed `crates/serat-app/webview` was rebuilt in production mode (`npm ci`, then `NODE_ENV=production npm run build` in `app/`) at task #116 and includes the pdf.js chunk and worker; its URL counts equal the bench build's. It is a committed artifact, so it goes stale again whenever `app/` changes without a rebuild: the scan of it is only as current as its last rebuild, and the fresh bench build is the strict one. The committed build is held to the same rule so that whatever is rebuilt into it next is checked.

The runtime check (a per-process connection log or packet capture on the reference machine through the gate week, naming the webview helper processes) belongs to `p1-gate-protocol.md`, which carries a row for it.
