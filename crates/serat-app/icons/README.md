# Icons — provisional

`icon.ico` is a placeholder: a 32×32 flat mark in the brand palette (indigo ground,
one brass thread, a paper bead), drawn to the rules in
`docs/03-design/ui/serat-identity.md` §Palette but **not** to any of the three
directions the identity document actually proposes.

It exists because `tauri-build` cannot produce a Windows binary without an `.ico`, so
without it the crate does not compile on Windows at all and nobody can measure
NFR-PRF-01.

`icon.png` is a placeholder of the same kind, added later (task #53) for the same
reason on the other platforms: `tauri::generate_context!()` embeds a default window
icon from a raster PNG regardless of target OS, and with none present it **panics at
compile time** — `error: proc macro panicked ... failed to open icon
.../icons/icon.png` — which is why `serat-app` had never once compiled on Linux before
this file existed, on any branch, in CI or out of it. It is not drawn at all — 32×32,
flat indigo (`#3B3486`), no thread, no bead, generated by a script rather than a hand
because the point was to stop a *build* failing, not to make a placeholder that looks
considered. Replace it the moment a real icon exists; do not let its presence stand in
for one being designed.

Owners: frontend-designer chooses and exports the mark; release-engineer owns the icon
set, the signed manifest and the installer (docs/06-release, architecture §10.1).
Replacing either file is expected and needs no coordination with tauri-app-dev.
